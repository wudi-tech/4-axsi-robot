# 坐标标定完整指南

> 四轴机械臂视觉系统（Eye-to-Hand）——从像素坐标到机器人基坐标的完整标定流程

---

## 一、坐标变换总体架构

本系统采用 **Eye-to-Hand** 配置：摄像头固定在机架上，俯视工作台，不随机械臂运动。
完整的坐标变换链如下：

```
摄像头拍到的画面
      │
      │  像素坐标 (u, v)
      │
      ▼
┌─────────────────────┐
│   相机内参标定        │  消除镜头畸变，建立"像素 → 相机坐标系"的映射
│  camera_intrinsic   │  输出：camera_matrix (K)、dist_coeffs (D)
└─────────────────────┘
      │
      │  相机坐标系 (Xc, Yc, Zc)
      │
      ▼
┌─────────────────────────────────────────────────┐
│         外参标定（二选一）                         │
│                                                  │
│  方案A：手眼标定（完整3D）                         │
│    hand_eye_extrinsic → T_cam2base (4×4刚体变换)  │
│                                                  │
│  方案B：单应矩阵（2D平面，无需3D位姿）              │
│    homography.npz → H (3×3透视变换矩阵)           │
└─────────────────────────────────────────────────┘
      │
      │  机器人基坐标系 (X, Y, Z)  单位：mm
      │
      ▼
   逆运动学 → 各轴关节角 → PCA9685 → 舵机
```

## 二、第一步：相机内参标定

### 2.1 为什么要做内参标定

普通摄像头镜头存在**径向畸变**（图像边缘变形）和**切向畸变**，直接用像素坐标计算会引入误差。
内参标定的目的是求出两组参数：

- **相机内参矩阵 K**：描述焦距和主点位置

```
K = [fx  0  cx]
    [ 0 fy  cy]
    [ 0  0   1]

fx, fy：X/Y 方向焦距（像素单位）
cx, cy：主点（光轴与成像平面的交点，通常接近图像中心）
```

- **畸变系数 D**：`[k1, k2, p1, p2, k3]`，k 为径向畸变，p 为切向畸变

### 2.2 标定板规格

本项目使用棋盘格标定板，配置参数（`config/settings.py`）：

| 参数 | 值 | 说明 |
|------|----|------|
| `CHESSBOARD_COLS` | 9 | 列方向内角点数 |
| `CHESSBOARD_ROWS` | 6 | 行方向内角点数 |
| `CHESSBOARD_SQUARE` | 24.5 mm | 单个方格边长 |
| `MIN_CALIB_IMAGES` | 15 | 最少有效采集帧数 |

> **内角点**：两个黑格相交的角点，不是方格的外边框角点。
> 9×6 内角点对应的棋盘格是 10×7 格的纸。

### 2.3 标定步骤

**第一步：打印标定板**

将棋盘格贴在硬板上（纸张不能弯曲），确保打印时比例正确，用直尺量一个方格确认是 24.5 mm。

**第二步：运行采集程序**

```bash
python tools/calibrate_camera.py
```

程序会打开摄像头实时画面，操作说明：
- 将棋盘格对着摄像头，保持画面中出现绿色角点框
- 按 **Space** 键拍照，采集 15 张以上
- 采集角度要求：**倾斜、旋转、不同距离**，覆盖图像各角落

```
推荐采集姿态示例：
  正对摄像头（中心位置）      ×1
  左倾 20°                  ×2
  右倾 20°                  ×2
  上倾 20°                  ×2
  下倾 20°                  ×2
  左上角、右上角、左下角、右下角各一张  ×4
  靠近摄像头（棋盘格填满大部分画面）   ×2
```

**第三步：执行标定计算**

采集完成后按 **c** 键自动计算，输出标定结果：

```
[Calibrator] 有效图像: 15 张
[Calibrator] 重投影误差 RMS = 0.6685 px   ← 越低越好，< 1.0 px 为合格
相机矩阵 K:
  [[1845.2   0.0  962.3]
   [  0.0 1844.8  534.1]
   [  0.0   0.0    1.0]]
畸变系数: [-0.412  0.201  0.001 -0.002  -0.089]
```

**第四步：保存结果**

```
data/calibration/camera_intrinsic.npz
```

### 2.4 RMS 误差评估标准

| RMS（像素） | 评估 | 处理建议 |
|-------------|------|----------|
| < 0.5 | 优秀 | 直接使用 |
| 0.5 ~ 1.0 | 合格 | 可正常使用（本项目当前 0.6685） |
| 1.0 ~ 2.0 | 较差 | 补充更多角度，重新标定 |
| > 2.0 | 不合格 | 检查棋盘格是否弯曲/打印比例是否正确 |

## 三、第二步（方案B）：单应矩阵标定

> **推荐优先使用此方案**。操作简单，10分钟完成，足以支撑桌面抓取任务。

### 3.1 原理

当机械臂只在**固定高度的工作台**上抓取目标时，问题退化为两个二维平面之间的映射：

```
图像平面（像素）  ←──→  工作台平面（mm）
```

单应矩阵 H 是一个 **3×3 的透视变换矩阵**，描述这两个平面的完整几何关系（包含旋转、平移、透视畸变）。

**数学表达（齐次坐标）**：

```
[X]         [u]
[Y]  =  H × [v]    （除以第三分量归一化）
[w]         [1]

最终结果：机器人坐标 X = X/w，Y = Y/w
```

H 有 **8 个自由度**（第 9 个分量固定为 1），每个对应点对提供 2 个方程，
因此**最少需要 4 组像素←→物理坐标的对应点对**。

**相比手眼标定的优势**：
- 不需要知道相机的三维位姿
- 不需要机械臂提供正运动学数据
- 操作步骤少，几分钟完成
- Z 坐标直接用配置的工作台高度 `WORK_PLANE_Z_MM`

**局限性**：
- 只对固定工作台高度有效，目标不能叠放
- 相机位置改变后必须重新标定
- 无法获得目标的真实 Z 坐标

### 3.2 Auto 模式（棋盘格自动标定，推荐）

**前提**：已完成相机内参标定（去畸变后精度更高）。

**操作步骤**：

```bash
python tools/calibrate_homography.py --mode auto
```

1. 将**棋盘格平放**在机械臂工作台面上
2. 程序实时检测角点，出现**绿色角点框**后按 **Space** 捕获
3. 程序自动计算单应矩阵并显示 RMS 误差
4. 按 **q** 保存退出

```
坐标系定义（auto 模式）：
  原点  = 棋盘格左上角第一个内角点
  X 轴  = 向右（沿棋盘格第一行方向）
  Y 轴  = 向下（沿棋盘格第一列方向）
  单位  = mm（由 CHESSBOARD_SQUARE = 24.5 mm 决定）
```

程序内部自动为 9×6=54 个角点建立对应关系：

```python
# 物理坐标自动计算
obj_pts[i] = (col × 24.5 mm,  row × 24.5 mm)
# 像素坐标由 OpenCV findChessboardCorners 自动检测
img_pts[i] = cornerSubPix(...)  # 亚像素精度
```

54 组点对保证了极高的标定精度，RMS 通常在 **0.5 ~ 2 mm**。

**快捷键**：

| 按键 | 功能 |
|------|------|
| Space | 捕获当前帧并计算 |
| r | 重置，重新检测 |
| q / ESC | 保存并退出 |

### 3.3 Manual 模式（手动点击标定）

没有棋盘格，或需要自定义坐标系原点时使用。

```bash
python tools/calibrate_homography.py --mode manual
```

**操作步骤**：

1. 在工作台上放置若干可识别的标记点（建议 6~8 个，分散在工作区四周）
2. 按 **f** 冻结画面（避免抖动导致点击不准）
3. **鼠标左键**点击图像中的一个标记点
4. 在终端输入该点的**实际物理坐标**（X Y，mm，空格分隔）：
   ```
   输入该点的物理坐标 X Y (mm)，例如 '0 0' 或 '245 120':
   > 0 0
   ```
5. 重复步骤 3-4，至少完成 4 个点（建议 6~8 个）
6. 按 **c** 计算单应矩阵，查看各点误差
7. 按 **q** 保存退出

**标记点布置建议**：
```
工作台俯视图，建议点位分布：

  P1 ──────────── P2
  │                │
  │   工作区域      │
  │                │
  P3 ──── P5 ──── P4
         P6

- 覆盖工作区域的四个角
- 加 1~2 个中间点
- 测量时用钢直尺，精度尽量到 0.5 mm
```

**快捷键**：

| 按键 | 功能 |
|------|------|
| 鼠标左键 | 添加一个点（之后在终端输入物理坐标） |
| f | 冻结 / 解冻画面 |
| u | 撤销最后一个点 |
| c | 计算单应矩阵 |
| r | 清空所有点重新开始 |
| q / ESC | 保存并退出 |

## 四、机器人基坐标系对齐

单应矩阵标定完成后，坐标输出是**标定坐标系**（原点取决于标定时选的参考点），而机械臂运动需要的是**机器人基坐标系**（原点在 J1 轴中心）。两者必须对齐才能正确控制机械臂。

```
单应矩阵输出                   机器人基坐标系
─────────────                  ─────────────────
原点 = 棋盘格左上角 / 手选参考点   原点 = J1 旋转轴中心
X → 标定时的参考方向              X → 机械臂正前方
Y → 标定时的参考方向              Y → 机械臂左侧
```

### 4.1 方法一：标定时直接以机器人基坐标系为参考（最简单）

使用 **Manual 模式**，选取几个相对于 J1 轴中心**已知距离**的点作为标定点，输入物理坐标时直接输入该点距离 J1 轴中心的距离（mm）。

```bash
python tools/calibrate_homography.py --mode manual
# 点击图像中一个标记点后，输入它相对于 J1 轴中心的坐标
# 例如：机械臂正前方 200mm 处输入 "200 0"
```

这样标定出的 H 矩阵**直接输出机器人基坐标**，后续无需任何转换。

**验证**：运行 verify 模式，鼠标点击机械臂底座正前方量好的某个位置，
终端坐标应与实测距离吻合（误差 < 3 mm）。

### 4.2 方法二：Auto 标定后加平移偏移（快速）

用棋盘格 Auto 模式完成标定后，量出棋盘格原点（左上角第一个内角点）相对于 J1 轴中心的偏移，在代码中补偿：

```python
# 实测棋盘格原点相对于 J1 轴中心的偏移（mm）
ORIGIN_OFFSET_X = 120.0   # 需要用钢直尺实测
ORIGIN_OFFSET_Y = -80.0   # 需要用钢直尺实测

# 转换时减去偏移
homo_xy = transform.pixel_to_robot_homography(u, v)[:2]
robot_x = homo_xy[0] - ORIGIN_OFFSET_X
robot_y = homo_xy[1] - ORIGIN_OFFSET_Y
```

> 如果棋盘格摆放时与机械臂 X/Y 轴方向不平行，还需要加旋转补偿。
> 建议摆放棋盘格时让其行列方向与机械臂坐标轴对齐，避免引入旋转。

### 4.3 方法三：TCP 触碰标定（最精确）

让机械臂末端实际**触碰**工作台上的已知标记点，用正运动学获取机器人坐标，同时记录相机像素坐标，用这批点对直接重算单应矩阵。

**步骤**：

1. 在工作台上贴 6~8 个小圆点标记，分散分布
2. 手动调节关节角，让末端精确触碰每个标记点
3. 记录每次触碰时的数据：
   - 像素坐标：从相机图像中读取标记点中心
   - 机器人坐标：调用 `arm.forward_kinematics()` 获取末端 XY
4. 用这批点对重新计算单应矩阵

```python
from robot.arm_controller import ArmController
from tools.calibrate_homography import compute_homography, save_homography
import numpy as np

img_pts  = []   # 像素坐标，手动从图像读取
robot_pts = []  # 机器人坐标，FK 计算

with ArmController() as arm:
    arm.home()
    # 手动调节关节角让末端触碰标记点后，记录：
    angles = arm.get_joints()          # 当前关节角
    R, t   = arm.forward_kinematics(angles)
    robot_pts.append([t[0], t[1]])     # 末端 X, Y (mm)
    # img_pts.append([u, v])           # 手动填入对应像素坐标

img_pts  = np.array(img_pts,   dtype=np.float32)
robot_pts = np.array(robot_pts, dtype=np.float32)
H, rms = compute_homography(img_pts, robot_pts)
save_homography(H, rms, img_pts, robot_pts)
print(f"TCP 触碰标定完成，RMS = {rms:.2f} mm")
```

**优点**：不需要量尺子，坐标直接由 FK 提供，精度由正运动学精度决定。

### 4.4 方法四：ArUco 标记动态定位

在机械臂底座旁**固定贴一个 ArUco 标记**，测量一次它相对于 J1 轴的固定偏移。
此后每次相机移动重标定后，通过检测 ArUco 自动恢复基坐标系原点，无需重新量尺子。

```python
from tools.debug_detectors import ArucoDetector

# ArUco 标记中心相对于 J1 轴中心的固定偏移（量一次，永久有效）
ARUCO_TO_BASE_X = -45.0   # mm，实测
ARUCO_TO_BASE_Y =  30.0   # mm，实测

detector = ArucoDetector()
results = detector.detect(frame)

if results:
    # 标记中心的像素坐标
    marker_px = results[0].center_px
    # 单应矩阵转为平面坐标
    marker_xy = transform.pixel_to_robot_homography(*marker_px)[:2]
    # 加固定偏移得到机器人基坐标系原点
    base_origin = marker_xy + np.array([ARUCO_TO_BASE_X, ARUCO_TO_BASE_Y])
    # 目标坐标转换到机器人基坐标系
    robot_xy = target_xy - base_origin
```

**优点**：相机位置改变后，只需重做单应矩阵标定，不用重新量偏移。
项目中 `ArucoDetector` 已实现，可直接使用。

### 4.5 方法五：最小二乘拟合 2D 刚体变换（鲁棒性最好）

收集 N 组对应点对后，用 SVD 拟合两个坐标系之间的旋转 + 平移，
比单点偏移补偿更能抵抗测量噪声。

```python
import numpy as np

# N 组对应点（N >= 3，越多越好）
# homo_pts:  单应矩阵输出的坐标
# robot_pts: 同一点的机器人基坐标（TCP 触碰法测出）
homo_pts  = np.array([[120, 80], [200, 80], [200, 160], [120, 160]], dtype=float)
robot_pts = np.array([[ 80, 40], [160, 40], [160, 120], [ 80, 120]], dtype=float)

# 质心对齐
hc = homo_pts.mean(axis=0)
rc = robot_pts.mean(axis=0)

# SVD 求最优旋转矩阵
U, _, Vt = np.linalg.svd((robot_pts - rc).T @ (homo_pts - hc))
R2d = U @ Vt
if np.linalg.det(R2d) < 0:   # 处理反射情况
    Vt[-1] *= -1
    R2d = U @ Vt
t2d = rc - R2d @ hc           # 平移向量

def homo_to_robot(xy: np.ndarray) -> np.ndarray:
    """标定坐标系 → 机器人基坐标系"""
    return R2d @ np.array(xy) + t2d
```

### 4.6 各方法对比

| 方法 | 操作难度 | 精度 | 相机移动后 | 当前可用 |
|------|----------|------|-----------|---------|
| Manual 标定直接输入机器人坐标 | 低 | 中（依赖尺子精度） | 重新标定 | ✅ |
| Auto 标定 + 平移偏移补偿 | 低 | 中 | 重新量偏移 | ✅ |
| TCP 触碰标定 | 中 | 高（依赖 FK 精度） | 重新触碰 | ✅（手动调节关节） |
| ArUco 标记动态定位 | 低 | 中 | 仅重做单应矩阵 | ✅（代码已有） |
| 最小二乘刚体变换 | 中 | 高 | 重新采集点对 | ✅（配合前几种） |
| 手眼标定（完整3D） | 高 | 最高 | 重新标定 | ⬜（等IK完成） |

**推荐组合**：
```
当前阶段：Auto 单应矩阵 + TCP 触碰 + 最小二乘拟合
          → 精度高，操作可行，无需 IK

相机固定后：在底座贴 ArUco 标记
          → 下次相机移动只需重做单应矩阵，原点自动恢复

IK 完成后：换用完整手眼标定
          → 支持三维空间抓取，精度最高
```

## 六、第二步（方案A）：手眼标定（完整3D，待完成）

### 6.1 原理

手眼标定求解的是**相机坐标系相对机器人基坐标系的刚体变换** T_cam2base（4×4 矩阵）：

```
P_base = T_cam2base × P_cam

T_cam2base = [R | t]    R: 3×3 旋转矩阵
             [0 | 1]    t: 3×1 平移向量
```

**标定方程（AX = XB 问题）**：

```
让机械臂运动到 N 个不同位姿，每次同时记录：
  A_i = T_base2gripper[i]   （机器人控制器提供，正运动学）
  B_i = T_target2cam[i]     （相机观测棋盘格，solvePnP 计算）

求解：A_i × X = X × B_i   其中 X = T_cam2base
```

这是一个经典的"手眼标定方程"，OpenCV 提供了多种求解算法（Tsai、Park 等）。

### 6.2 操作步骤（待机械臂联调后执行）

**准备工作**：
- 将棋盘格固定在机械臂**末端夹爪**上（不能松动）
- 确保相机固定不动
- 已完成相机内参标定

**采集流程**：

```bash
python tools/calibrate_hand_eye.py
```

1. 手动控制机械臂运动到第一个位姿
2. 程序自动拍照检测棋盘格，同时记录机械臂末端位姿（来自正运动学）
3. 移动机械臂到下一个位姿，重复采集
4. 至少采集 **10 组**（`HAND_EYE_MIN_POSES = 10`），越多越精确
5. 按 **c** 执行标定，保存结果

**位姿多样性要求**（影响标定精度）：
```
每次移动要确保：
  ✓ 平移量 > 50 mm（X、Y、Z 方向都要有覆盖）
  ✓ 旋转量 > 15°（各轴旋转都要有）
  ✗ 避免纯平移（没有旋转）
  ✗ 避免位姿太相似
```

## 九、常见问题

| 现象 | 原因 | 解决方法 |
|------|------|----------|
| auto 模式检测不到棋盘格 | 光线不足 / 棋盘格弯曲 / 角度过大 | 补光，压平棋盘格，调整摆放角度 |
| RMS > 5 mm | 标定点分布太集中 / 手动输入坐标有误 | 确保点分散在工作区四周，重测物理坐标 |
| verify 网格明显弯曲 | 忘记去畸变（内参未加载） | 确认 `camera_intrinsic.npz` 存在 |
| 抓取偏差系统性地偏向一侧 | 坐标系原点定义偏移 | 重新标定，注意原点位置和机器人基坐标系对齐 |
| 相机轻微移动后误差增大 | 单应矩阵对相机位置敏感 | 固定好相机后重新标定 |
| 手眼标定 R 不是正交矩阵 | 位姿多样性不足 | 增加更多不同方向的位姿，特别是旋转分量 |
