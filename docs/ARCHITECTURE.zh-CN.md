# 系统架构与交互逻辑

## 数据流

固定式 USB 相机 → 后台线程最新帧 → YOLO 三类检测 → 目标中心像素 → 相机去畸变 → 工作平面 homography → 交互决策 → 四轴 IK → 舵机角度/count 映射 → CH347 USB-I2C → PCA9685 → m0–m3 关节与 m4 夹爪。

相机按 1920×1080、MJPG、30 fps 请求采集。30 fps 是配置目标，本次未测量实际帧率或端到端延时。homography 适用于已标定平面，不提供通用三维深度。

## 模块对应

| 模块 | 文件 | 作用 |
|---|---|---|
| 最新帧采集 | `camera/capture.py` | 后台取帧，锁保护最近一帧，减少排队积压 |
| 视觉管道 | `vision_pipeline.py` | 检测、平面坐标和预览的组合 |
| 物体/人手 | `detection/yolo_detector.py`、`hand_detector.py` | 三类检测和手掌中心像素 |
| 坐标 | `transform/coordinate_transform.py` | 相机内参、单应矩阵，另保留手眼工具接口 |
| 行为入口 | `main.py` | voice、keyboard、cat、detect、list_cameras 分发 |
| 语音 | `robot/voice_controller.py` | 后台识别、指令队列、TTS、关键词/拼音别名 |
| 运动和硬件 | `robot/arm_controller.py`、`servo.py`、`pca9685.py`、`ch347_i2c.py` | FK/IK、软限位、PWM 和 USB-I2C 封装 |
| 配置 | `config/settings.py` | 相机、模型、标定文件与抓放配置 |
| 维护 | `tools/` | 标定、训练、标注转换、颜色/ArUco 调试 |

## 普通抓取与键盘

voice 和 keyboard 复用 `_pick_by_voice_command()`：按类别筛选当前帧检测，选择置信度较高的目标，转换坐标并接近/抓取；随后等待反馈。键盘使用后台 `input()` 线程和队列，主循环轮询命令，输入不阻塞相机预览。运动序列本身仍使用同步调用，不应称为全程非阻塞控制。

## 拟猫流程

1. 接收目标类别指令，保留当前检测候选列表。
2. 随机选取尚未尝试的候选索引；`CAT_EXCLUDE_BEST=False`，默认不强制排除高置信度对象。
3. 坐标转换、接近、闭爪、抬起，等待最长约 10 秒反馈。
4. `feedback_bad`：放回、松爪、换未尝试对象；`feedback_good`：固定区域放置，执行奖励；超时则按对应分支结束。
5. 奖励时尝试检测手掌，并执行约 5 秒的预设摆动；失败时使用固定位置作为降级行为。

随机策略由候选数和筛选结果决定，没有已验证的固定指错率。当前调试终端仍打印类别、判断及坐标，不能声称已经实现“绝不向用户暴露目标信息”的完整界面约束。

## 保留的动作配置

当前源与归档一致：闭爪 `15.0°`；正确反馈后的 `_place_object_at_pick_zone()` 先原地升至 `150 mm`，再移到 `(160, 0, 150)`，下降至 `(160, 0, 0)`、松爪并抬回 `150 mm`。普通与拟猫正确反馈分支均调用该函数。

抓取后的反馈等待高度仍分别使用普通模式 `80 mm`、拟猫模式 `100 mm`，并非所有抬升都已统一为 150 mm。150 mm 仅描述成功放置路径中的抬升高度；没有硬件复验其可达性或碰撞裕量。历史早期 5° 闭爪请求不覆盖当前源 15°。

该函数检查前三段 `move_to_xyz()` 的返回值，但最后一次抬回没有检查结果；其他动作分支也有未检查返回值。归档保留源码行为，不据此给出完整运动安全保证。
